## Unsent posts appear to have completed delivery

**confirmed:** analytics availability is based only on whether `post.channels` contains the channel (`src/AnnouncementsPage.tsx:153-182`). It does not account for `Draft` or future `Scheduled` status. Opening analytics for the included draft therefore reports its full Feed audience as Delivered, and Mobile Push and WhatsApp use generated delivery, open, read, and click counts even when a configured post has never been published. Treat unsent posts as unavailable or present a clearly separate pre-delivery estimate state; only derive delivery funnels for posts that have actually published.

## In-App tab contains Mobile Push reporting

**confirmed:** the exact tab label `In-App` is wired to the `in-app` analytics key, but that key checks `Mobile push`, derives push delivered/opened/action-click counts, and renders a push preview labeled `Internal Mobile push` (`src/AnnouncementsPage.tsx:164-173`, `src/AnnouncementsPage.tsx:482-492`). This makes the requested In-App channel report a different delivery mechanism. Either provide actual In-App metrics under this tab or consistently rename the underlying channel and content so the tab is not presenting push data as In-App data.

</details>
