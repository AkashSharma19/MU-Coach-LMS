# Competition-scoped awards with approval governance and accessible entry actions

The change moves groups, awards, scores, and reward policy into per-competition state, with list counts derived from each competition’s current groups. Award submission now enforces configured limits and negative-point policy, while approval-required entries remain pending until explicitly approved; group deletion is blocked whenever award history exists. Card and compact views now expose semantic detail buttons, and the shared modal traps focus and uses unique generated title IDs. **Watch for:** **confirmed** focus restoration still fails for auto-focused dialogs and for list-level edit dialogs whose opener is unmounted as detail state replaces the list.

**Verdict**: NEEDS_CHANGES

## High-level view

Competition records now own independent group, award, and reward datasets. The original records seed only `comp-1`, other competitions start empty, and group/participant counts are calculated from scoped groups.

Pending awards are excluded from score changes and normal posted metrics until approval. The Rewards Configuration tab provides Approve and Reject actions, while deletion checks every award status to preserve group history.

Both competition list modes have keyboard-focusable View/Open buttons. The modal moves focus inside and wraps Tab navigation, but captures the restoration target after `autoFocus` can move focus; list Edit also removes its triggering button before the dialog opens (**confirmed**).

Capturing earlier alone cannot restore focus to that removed control; this path needs a stable fallback, or it must keep the opener mounted until the dialog closes (**confirmed**).
