Both list presentations expose native buttons for entering detail. The modal captures the active opener during render, before descendant `autoFocus` runs, and list-level editing no longer changes selection, so its opener remains mounted for cleanup-time restoration.

## Focus ownership survives modal auto-focus and list editing

The modal snapshots `document.activeElement` into a ref during its initial render and copies that reference into the effect cleanup closure. Descendant `autoFocus` therefore cannot replace the restoration target. `editingCompetitionId` is independent from `selectedCompetitionId`, so opening Edit from the list preserves the list and its triggering button until the dialog closes; the cleanup can restore focus to the original live element.

The same modal installs Tab/Shift+Tab wrapping across current focusable descendants, falls back to the dialog panel when none exist, and leaves Escape dismissal routed through the page’s existing modal state. Generated title IDs avoid collisions between dialog instances.

## Scoped scores, approvals, and audit history remain aligned

Each competition owns its groups, awards, and reward configuration, with only `comp-1` receiving the original records and other competitions receiving independent empty state. Counts are recomputed from each competition’s current groups, so group and membership mutations flow back to both list layouts without metadata synchronization.

Award submission validates the configured magnitude range and negative-point permission. Approval-required entries are stored as Pending without changing group points or posted logs; approval posts and applies the points once, while rejection preserves a Rejected audit entry. Group deletion checks the complete scoped award collection rather than only posted rows, preserving pending and rejected history as well as posted history.
