# Unified campus feed and broadcast management

The change adds a Communication > Announcements workspace for creating, scheduling, publishing, previewing, and measuring campus posts. It keeps post state and simulated delivery local while covering the requested management table, two-step editor, student feed, and analytics surfaces. The App integration is narrow and uses the existing navigation and notification patterns. **Watch for:** **confirmed** editor focus resets that make text entry unusable; **confirmed** audience loss when editing; **confirmed** repeatable acknowledgements; **confirmed** unsupported drag-and-drop uploads; **confirmed** false clipboard success and incomplete dialog focus handling.

**Verdict**: NEEDS_CHANGES

## High-level view

The unified editor centralizes content, priority, audience, channels, and scheduling, but its focus effect is coupled to an unstable close callback. Every form state update reruns initial-focus behavior, interrupting title and body entry after each change (**confirmed**).

Posts retain only a display-formatted audience string. Edit reconstructs that string as either all programs or the first program and clears cohort, term, and section, so editing an existing targeted post silently changes its audience (**confirmed**).

Student preview actions are local as requested, but acknowledgement has no per-student acknowledged state and remains actionable indefinitely. Each click increments aggregate analytics, allowing one preview user to inflate the acknowledgement count (**confirmed**).

The attachment picker advertises a restricted set of file formats, while validation checks size only. Files dropped onto the target bypass the input's `accept` hint and any unsupported file under 15 MB is stored (**confirmed**).

The student preview and analytics drawer respond to Escape but do not contain focus or restore it to their launch controls. Clipboard-unavailable sharing also reports that a link was copied even though no fallback copy path ran (**confirmed**).

<details><summary>Details</summary>

## Editor focus lifecycle blocks content entry

`Overlay` runs initial focus and focus restoration in an effect depending on `onClose`, while the editor passes `onClose={() => setEditorOpen(false)}` (**confirmed**). Typing into any controlled field rerenders `AnnouncementsPage`, creates a new callback, cleans up the effect, and runs it again; focus returns to the first enabled control. In practice, title and body entry is interrupted after each keystroke. Stabilize the close handler or decouple initial focus/trap setup from callback identity.

The same focus containment and opener restoration are absent from `AnalyticsDrawer` and `StudentPreview`, allowing Tab to reach the obscured application and leaving focus in an unpredictable place when either view closes (**confirmed**). Reuse the overlay focus primitive or implement equivalent drawer/full-screen-dialog behavior.

## Audience targeting is not round-trippable through edit

A post stores audience only as the rendered `audience` string. `openEdit` maps `All students` to every program, maps every other audience to `PROGRAMS[0]`, and always clears cohort, term, and section (**confirmed**). Editing the seeded Undergraduate Programme draft therefore opens as PGP Technology & Business Management, while the targeted Cohort 7 notice loses its cohort selection; saving persists the altered audience. Store the structured hierarchy on each post and prefill it directly.

## Acknowledgement can be submitted repeatedly

`acknowledge` increments the aggregate count, but preview state never records that the current student acknowledged the notice and the button never changes or disables (**confirmed**). Repeated clicks from the same preview session increase analytics until the audience cap. Track acknowledged post IDs locally, make the operation idempotent, and render the completed state.

## Attachment type restrictions are presentation-only

The hidden input declares `accept="image/*,.pdf,.docx,.zip"`, but `addFiles` accepts every file not exceeding 15 MB (**confirmed**). Drag-and-drop is not governed by the input attribute, so executables and arbitrary formats are added without an inline rejection. Validate MIME type and/or extension in `addFiles` for both picker and drop paths and report rejected types alongside oversized files.

## Preview sharing and dialog accessibility have incomplete fallbacks

`share` conditionally writes only when `navigator.clipboard` exists, then unconditionally emits “Post link copied to clipboard” (**confirmed**). In an unavailable Clipboard API environment, no copy occurs and the fallback notification is never used; branch explicitly to the fallback path and avoid claiming success.

Both preview and analytics implement Escape dismissal but omit the trap and restoration behavior used by the editor overlay (**confirmed**). Keyboard navigation can leave these modal surfaces for hidden page controls, and close does not return focus to “Student preview” or “View report.” Apply modal focus containment and opener restoration to both.
